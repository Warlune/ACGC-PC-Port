# Three-town development preview

The opt-in `ACO_DEV_EAST` build (legacy internal option name, defaults OFF) uses 21 columns: a complete newly generated seven-column west town, the original seven-column center town, and a newly generated seven-column east town. Each town retains its mountain borders, native beaches/ocean, railway, river, cliffs, bridges and landmark placements. Southwest and southeast coastal shoulders now connect the towns in the same outdoor scene, around shortened mountain ends. Duplicate stores/stations/landmarks are intentional for this prototype.

`pc/tools/generate_dev_town.c` links the original `m_random_field_ovl.c`, combination table and native RNG at the original 7x10 dimensions. Its small river-direction adapter matches the lookup in `m_random_field.c`. Different saved seeds generate the two sides. Do not run the generator against the widened client dimensions: the game's authored base templates are seven columns wide. The assembly tool copies the corresponding native foreground templates directly from `fgdata.bin` on the user's local disc; these are real generated layouts, not mirrored copies or hand-painted grass.

`tools/aco/make-world-preview.py` assembles the generated sides around a copy of a normal GAFE01 save, then applies the shared `world-generation.py` coastal rule. It validates source/output checksums, preserves all 30 original playable foreground acres and buried-item flags byte-for-byte at a seven-acre eastward offset, copies the fixed fields around resized arrays, and mirrors the main save into its backup sector. Only the shared border columns receive mountain caps, connecting beaches and ocean. It refuses to overwrite an output or edit the source. Expanded saves are 548928 bytes, **not standard GameCube saves**. Layout JSON comes from compiling `pc/tools/dev_east_layout.c` with and without the development define. Keep this runtime/save directory isolated from normal builds.

`Build World Dev.cmd` builds the client. Launch with `--dev-world`, optionally `--dev-west` or `--dev-east`. The dev boot chooses an existing resident, enables the RTC normally initialized by the title, skips character/title setup, and chooses an empty tile on a flat acre in the selected region. Every restart reuses that resident. Resetti is disabled and continuous acre movement enabled in the dev copy.

`--dev-sw` and `--dev-se` start on the coastal connections. Add `--dev-coast-test` to walk each route to the adjacent town and back through normal controller/collision code; it prints PASS only after the return. This test mode is never enabled by the regular player launchers. `connect-world-coast.py` upgrades a copy of an existing triple-town development save using the same shared rule; it also refuses overwrites. `test-world-generation.py GENERATOR DISC LAYOUT --seeds 60` verifies generated layouts, interior preservation, clear shoulders and idempotence. Route metadata supplies future story-gate coordinates; gates are not enabled yet.

Native exterior mountain geometry occupies a 160-unit strip inside a 640-unit border acre. Internal joins stretch those native strips to fill the shared mountain ridge; the collision grid uses the same horizontal mapping. Coastal caps use a matching depth mapping and dry native grass underlay, removing their original exterior-ocean patch. Outer world mountains keep their original geometry. This is a prototype composite of existing assets, not a new authored mountain asset set.

The PC renderer now retains 16 foreground acres and draws a 5x5 terrain region; slot bitfields support all 16 entries. Retained slots survive window changes, outgoing slots are freed before replacements, and interior scenes retain their original allocation counts. Actor culling and outdoor far clipping expand with camera distance above 100%. Texture-cache lookups use indexed buckets with full content/palette identity and rebuild after eviction. Diagnostic reports are buffered and flushed once per report to avoid synchronous writes per printf field, especially on NAS-backed paths.

This is a terrain/layout preview. Global town services, NPCs, landmark uniqueness, original map-panel labels, schedules/train service and world metadata still assume one logical town. Duplicated buildings are not independent fully integrated businesses. Story locks, co-op integration and the actual overhead-rendered minimap remain further work. The faint illustrated minimap displays the widened world.
